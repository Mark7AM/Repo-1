Azure Activity Log: What matters most

Azure Activity Log records control-plane events such as resource creation, updates, deletes, permission changes, and policy actions. It helps you answer: what changed, when it happened, who initiated it, and whether it succeeded.

1. Time and sequence

The timestamp tells you when the event happened. Review the order of events to spot suspicious patterns such as a VM being created, followed by a policy change or a deallocation.

2. Resource and scope

Look at the resource group, subscription, and resource name. This shows exactly what was affected and whether the change occurred at the app, network, or infrastructure level.

3. Operation details

The operation name tells you the specific action, such as Microsoft.Compute/virtualMachines/write or Microsoft.KeyVault/vaults/delete. This is the clearest clue about the change.

4. Caller and identity

Check who initiated the action. Azure records the caller identity, including whether it was a user, service principal, managed identity, or automated system process.

5. Status and result

The status shows whether the action was successful, failed, or started. Failed operations may indicate permission issues, quota limits, or misconfigured resources that need follow-up.

6. Correlation and audit trail

Correlation IDs and activity IDs help you connect a series of related events across Azure services so you can trace the full lifecycle of a request or security investigation.

Typical Azure activity log event

{
  "timestamp": "2026-10-10T14:22:10Z",
  "operationName": "Microsoft.Compute/virtualMachines/start/action",
  "resourceGroup": "rg-prod-app",
  "resourceId": "/subscriptions/abc/resourceGroups/rg-prod-app/providers/Microsoft.Compute/virtualMachines/app-vm-01",
  "caller": "user@contoso.com",
  "status": {
    "value": "Succeeded",
    "localizedValue": "Succeeded"
  },
  "correlationId": "7abf7d34-2a12-4b6d-9a87-e7a05d66b829"
}

How to interpret an Azure event

  1. Check the time to confirm when the action occurred.
  2. Identify the resource and subscription or resource group it touched.
  3. Read the operation to understand the exact action taken.
  4. Review the caller to determine whether the activity was expected.
  5. Confirm the result and investigate any failed or unusual events.

Important fields to review

Field Why it matters
Event timestamp Shows when the change occurred
Operation name Identifies the specific Azure action
Resource ID Pinpoints the exact resource involved
Caller Shows who or what initiated the change
Status / result Indicates success or failure
Correlation ID Links related activity together
